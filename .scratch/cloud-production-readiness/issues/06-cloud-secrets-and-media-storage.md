# 06 云密钥与媒体存储策略

Type: task
Status: open
Stage: 云端落地
Blocked by: 02, 05

## 目标

明确单机首发和未来横向扩展下的 Provider、SMTP、支付密钥及用户媒体存储方案，并实现最小权限和可恢复性。

## 问题分析

- 当前密钥 Adapter 依赖宿主机 `0700/0600` 权限和磁盘加密，不提供 KMS 静态加密。
- 当前媒体生产装配使用本地目录；现有 S3 兼容 Adapter 只覆盖部分对象操作，尚不能直接替代完整读写路径。
- 数据库保存媒体对象键和密钥引用；数据库、媒体和密钥必须按同一恢复点处理。
- 多主机部署不能继续依赖单机目录，但首发不应为了未来扩容引入未验证复杂度。

## 设计方案

- 单机首发允许继续使用加密云盘和文件 Adapter，但密钥目录与媒体目录分盘/分路径、最小权限、独立备份。
- 生产密钥优先迁移到云 Secret Manager/KMS；实现新的 `ProviderSecrets` Adapter，数据库仍只保存不透明引用。
- 对象存储分阶段：先完成全套 put/read/copy/delete/metadata 契约，再切换生产；桶默认私有、阻止公共 ACL、启用服务端加密和生命周期策略。
- Web 与 Worker 使用不同 IAM：Web 可管理配置密钥，Worker 只读执行所需密钥；媒体权限按实际读写职责授予。

## 实施步骤

### 1. 分析问题

- 枚举 Provider、SMTP、支付和用户 LLM 密钥的创建、读取、轮换、删除路径。
- 枚举媒体临时、持久、释放和过期状态对应的对象操作。

### 2. 设计确认

- 决定首发是否立即使用 Secret Manager/对象存储，记录 ADR 和迁移/回滚策略。
- 定义 IAM、KMS key policy、对象键命名、生命周期和数据驻留区域。

### 3. 修改代码

- 实现并配置 Secret Manager/KMS Adapter，补齐密钥轮换和引用清理测试。
- 如本阶段启用对象存储，补齐 S3 Adapter 的完整读写契约和生产装配。
- 增加配置探针，启动时验证权限但不记录密钥内容。
- 更新 Compose/IaC、环境变量和备份文档。

### 4. 质量检测

- 使用模拟客户端覆盖成功、权限拒绝、网络中断、重复删除和轮换失败。
- 在预发布验证旧密钥失效、新密钥生效、迟到任务语义不变。
- 验证桶和 Secret 无公网权限，日志与数据库不出现明文。

## 完成标准

- 密钥和媒体的生产存储方案有 ADR、IAM 和恢复方案。
- 密钥轮换不要求修改数据库业务字段，也不泄露原值。
- 若启用对象存储，所有媒体生命周期测试在真实兼容服务上通过。
