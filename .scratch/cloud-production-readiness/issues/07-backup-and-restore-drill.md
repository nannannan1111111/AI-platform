# 07 自动备份与恢复演练

Type: task
Status: claimed
Stage: 可运维
Blocked by: 05, 06

## 目标

自动备份 PostgreSQL、媒体、密钥和部署元数据，并证明可以在隔离环境按同一恢复点恢复。

## 问题分析

- 当前文档定义了备份内容，但没有调度、保留、校验、告警或恢复脚本。
- 只恢复数据库会产生缺失媒体/密钥引用，只恢复文件又会失去账户归属和账务事实。
- Provider、SMTP 和支付密钥备份必须加密并严格限制访问。
- “备份任务成功”不等于备份可恢复。

## 设计方案

- 定义 RPO/RTO 后选择托管 PostgreSQL PITR + 周期逻辑备份的组合。
- 每次备份生成恢复点 manifest：数据库备份标识、媒体快照、密钥快照、镜像 digest、迁移 head、配置版本和校验和。
- 备份跨故障域加密保存，采用日/周/月分层保留和对象锁定或防误删策略。
- 恢复流程默认进入隔离网络，先校验 manifest，再恢复数据库、媒体、密钥，最后启动迁移/应用验收。

## 实施步骤

### 1. 分析问题

- 统计数据量、增长率、备份窗口，确认云盘/对象存储一致性能力。
- 故障注入：缺失媒体、错误密钥快照、损坏 dump，记录当前失败表现。

### 2. 设计确认

- 评审 RPO/RTO、保留期、加密 key、访问审批、恢复责任人和演练频率。
- 明确业务一致性方案：短暂停写、快照协调或应用级恢复点标记。

### 3. 修改代码

- 新增备份、manifest、校验和恢复脚本及调度配置。
- 增加备份成功时间和恢复点完整性指标。
- 编写逐步恢复与灾难切换 Runbook。

### 4. 质量检测

- 每日自动校验备份可读性；至少每月在隔离环境全量恢复。
- 恢复后验证登录、余额、画布、代表性媒体、密钥引用和任务历史。
- 记录真实 RPO/RTO，并验证损坏/缺件恢复点会被拒绝。

## 完成标准

- 自动备份有失败告警和保留策略。
- 最近一次隔离恢复演练成功，RPO/RTO 达标。
- 任一恢复点都能追溯到镜像摘要、迁移 head 和三类数据快照。

## Comments

### 2026-08-18 仓库侧先行实现

- 新增 `backend/app/backup_manifest.py` 与 `backend/scripts/backup_manifest.py`，支持恢复点元数据、文件 SHA-256、原子写入（0600）和完整性校验。
- 新增定向测试，覆盖完整恢复点、篡改文件拒绝和必填组件校验。
- `verify` 支持通过 `--file NAME=PATH` 将恢复后的文件映射到隔离目录，避免直接信任原机器绝对路径。
- 该实现不宣称已完成腾讯云 PITR、COS、KMS 或隔离恢复；真实云资源和 RPO/RTO 演练仍依赖任务 05/06 与用户后续凭据。

### 2026-08-18 备份校验指标

- `backup_manifest.py verify --metrics-file` 在校验成功或失败后原子输出 Prometheus textfile 指标，包含最新已验证恢复点创建时间、最近校验时间和完整性状态。
- 失败校验会把完整性置为 `0` 并保留上一次成功时间，避免错误刷新备份新鲜度；指标不含快照 ID、文件路径或凭据。
- 已补媒体/备份告警模板和恢复 Runbook；真实调度、PITR 连续性、采集 Agent 与恢复演练仍待腾讯云环境，任务保持 `claimed`。
