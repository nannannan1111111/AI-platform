# 08 可观测性与告警

Type: task
Status: claimed
Stage: 可运维
Blocked by: 05

## 目标

让 Web、Worker、PostgreSQL、媒体和 Provider 故障能够被及时发现，并通过统一标识快速定位。

## 问题分析

- 当前主要依赖 Uvicorn/Worker 普通日志与健康探针，没有统一请求 ID、指标、仪表盘或告警。
- 图片任务跨浏览器、Web、数据库、Worker 和 Provider，缺少关联字段会使排障依赖人工拼接。
- `/healthz` 与 `/readyz` 不表示 Provider、队列或备份正常。
- 日志必须避免连接串、Bearer、API Key、Cookie、用户图片和完整提示词泄露。

## 设计方案

- Web 接受或生成安全 `x-request-id`，在响应与结构化日志中返回；任务日志同时记录 task/attempt/provider request ID。
- 暴露受保护的 Prometheus 指标或接入云监控：HTTP、数据库池、队列、任务状态、Worker、Provider、媒体容量、支付通知和备份。
- 日志使用 JSON，字段 allowlist + 集中脱敏；错误详情向用户保持去敏投影。
- 先定义 SLI/SLO，再配置有持续窗口的告警，避免瞬时噪音。

## 实施步骤

### 1. 分析问题

- 绘制一次生成任务和支付通知的完整调用链，列出当前可用标识和缺口。
- 建立故障清单：Web 5xx、数据库池耗尽、Worker 停止、队列积压、Provider 失败、磁盘不足、备份过期。

### 2. 设计确认

- 选择监控/日志平台、保留期、采样策略、告警渠道和隐私边界。
- 定义仪表盘、阈值、值班责任和 Runbook 链接。

### 3. 修改代码

- 增加请求关联中间件、结构化日志和业务指标。
- 为 Worker 心跳/最后成功领取、队列最老任务年龄和 Provider 结果增加指标。
- IaC 配置日志采集、仪表盘、告警和通知渠道。

### 4. 质量检测

- 注入数据库不可用、Worker 退出、Provider 500、磁盘阈值和备份过期，确认告警触发与恢复。
- 自动扫描日志，确保测试 Token、Key、连接串和图片内容未出现。
- 从一个 request ID 成功关联到任务、attempt 和上游请求。

## 完成标准

- 核心 SLI 有仪表盘和告警，且每条告警链接到 Runbook。
- 关键故障在约定时间内被发现。
- 安全日志测试证明敏感信息不落盘。

## Comments

### 2026-08-18 仓库侧先行实现

- 新增请求关联中间件：安全接受/生成 `x-request-id`，响应回传并记录 HTTP 状态/延迟指标。
- 新增轻量 Prometheus 文本出口 `/metrics`，必须配置 `METRICS_TOKEN` 才可抓取；未配置时返回 404。
- 新增 JSON 日志 Formatter/Filter 和字段 allowlist，脱敏 Bearer、Cookie、API Key、数据库连接串、密码、提示词和图片字段。
- Worker 接入结构化日志、心跳、最后成功时间、在途任务、队列最老任务年龄及处理结果指标。
- Provider 图片提交和易支付通知入口分别增加低基数计数指标，不记录请求内容、凭据或用户提示词。
- SQLAlchemy Engine 装配连接池建立、借出、归还、当前占用、池大小和 overflow 指标；监听器幂等安装，不改变连接池参数或行为。
- 新增定向请求 ID、指标鉴权、日志脱敏测试；Ruff 已通过。当前环境缺少项目依赖，完整 pytest/mypy 需在 CI 或安装锁定依赖后运行。
- 真实腾讯云监控、通知渠道、Provider/数据库/磁盘故障注入和告警恢复验收仍未完成，因此工单保持 `claimed`。

### 2026-08-18 存储与备份告警模板

- `/metrics` 在鉴权成功后采集媒体卷总量、已用量、可用量和探测状态，不使用文件路径标签；探测失败时容量归零并显式上报失败。
- 新增 Prometheus 告警模板，覆盖媒体卷探测失败、使用率超过 80%、备份指标缺失、恢复点超过 26 小时和完整性失败，每条规则链接 Runbook。
