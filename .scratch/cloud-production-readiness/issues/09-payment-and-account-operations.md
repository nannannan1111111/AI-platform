# 09 支付与账户运营阻塞项

Type: task
Status: open
Stage: 收费发布
Blocked by: 03, 04

## 目标

补齐或明确收费首发所需的退款/拒付、密码找回和人工处置流程，避免出现无法闭环的用户资金与账户问题。

## 问题分析

- 当前支付成功通知与幂等入账已实现，但退款、部分退款和拒付自动通知尚未装配。
- 管理员可取消任务并退款冻结额度，但不等于向支付渠道退款。
- 当前只有登录后修改密码，没有忘记密码邮件流程。
- 直接上线收费会把这些缺口转移为高风险人工操作。

## 设计方案

- 先与实际支付网关确认退款/拒付协议、签名、金额精度和事件唯一键；所有资金事件追加审计事实，不改写历史账务。
- 自动化范围不足时，发布前必须提供双人复核的人工 Runbook 和每日对账。
- 密码找回使用单次、短 TTL、数据库只存摘要的令牌；成功后撤销该用户全部会话。
- 所有错误响应避免泄露邮箱是否注册。

## 实施步骤

### 1. 分析问题

- 获取支付网关正式文档和沙箱，列出成功、重复、乱序、部分退款、拒付和签名轮换场景。
- 建立账户找回威胁模型和邮件投递失败语义。

### 2. 设计确认

- 评审账务事件模型、幂等键、对账差异处理、审批权限和审计保留。
- 决定哪些能力必须自动化、哪些允许首发人工处理。

### 3. 修改代码

- 实现经确认的退款/拒付 Adapter、HTTP 验签、账务追加和管理投影。
- 实现密码找回令牌、SMTP 邮件、重置接口和全会话撤销。
- 增加每日对账脚本、人工处置页面/Runbook 和管理员审计日志。

### 4. 质量检测

- 沙箱验证重复和乱序通知不会重复冲正。
- 测试金额不匹配、错误 PID/签名、密钥轮换和部分失败回滚。
- 验证重置令牌一次性、过期、重发替换和成功后旧会话失效。

## 完成标准

- 每种资金异常都有自动或经批准的人工闭环。
- 每日对账能发现并告警差异。
- 用户可以安全找回密码，且接口不泄露账户存在性。
