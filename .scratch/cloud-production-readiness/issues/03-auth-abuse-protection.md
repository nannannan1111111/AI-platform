# 03 认证防滥用与登录风控

Type: task
Status: open
Stage: 公网安全
Blocked by: 01

## 目标

保护注册、登录和验证邮件接口，降低撞库、暴力破解、批量注册和邮件轰炸风险。

## 问题分析

- 当前认证端点没有服务端限流、失败退避或短时锁定。
- Web 有多个进程，单进程内存计数器会被绕过且重启后丢失。
- 只按 IP 限制会误伤 NAT 用户，只按邮箱限制又可被批量换邮箱绕过。
- 错误响应必须避免泄露邮箱是否注册，同时不能形成永久账号锁定 DoS。

## 设计方案

- 继续使用 PostgreSQL，不为限流单独引入 Redis。
- 新增短周期限流状态，按“可信客户端 IP + 规范化邮箱摘要 + 动作”联合计数。
- 建议初始策略：登录每 IP 10 次/10 分钟、每邮箱 5 次/10 分钟；注册每 IP 5 次/小时；验证邮件每账户 3 次/小时。阈值必须可配置并在预发布压测后确认。
- 登录失败采用有上限的短时退避；成功登录清理对应邮箱失败状态。
- 429 返回 `Retry-After`；登录失败保持统一文案。
- 限流记录只存最小摘要与时间，不保存明文密码、Token 或完整请求体。

## 实施步骤

### 1. 分析问题

- 为三个端点建立并发攻击测试，验证当前可无限请求。
- 明确信任代理后的客户端 IP 获取规则，与任务 04 共用实现。

### 2. 设计确认

- 评审表结构、原子更新 SQL、过期清理、隐私保留期和管理员解锁路径。
- 确认限流失败时数据库不可用的 fail-closed/fail-open 策略。

### 3. 修改代码

- 新增 Alembic 迁移、限流 Port/SQLAlchemy Adapter 和认证服务集成。
- 为注册、登录、邮件重发增加动作级策略和 `Retry-After`。
- 增加结构化安全事件日志和限流指标，不记录敏感字段。
- 更新运维文档和环境变量示例。

### 4. 质量检测

- 单元测试窗口边界、并发原子性、成功清理、IPv4/IPv6 和代理场景。
- PostgreSQL 多进程集成测试证明请求不能通过切换 Worker 绕过。
- 负载测试验证正常用户不会在目标并发下被误限流。

## 完成标准

- 三类认证端点都有跨进程限流。
- 撞库与邮件轰炸测试在阈值后稳定返回 429。
- 日志、数据库和响应均不泄露凭据或账户存在性。
