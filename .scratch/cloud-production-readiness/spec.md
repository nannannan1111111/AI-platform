# 云端生产就绪计划

## 背景

当前版本已经能构建生产镜像，并可用 PostgreSQL、Web、Generation Worker、媒体目录和密钥目录组成单机生产拓扑。手工质量检查已经通过，但仓库尚未自动执行发布门禁，公网安全、云基础设施、备份恢复、监控告警和正式验收仍需完成。

## 已完成基线

- 后端完整回归：552 passed，Windows 仅跳过 1 项 Linux 文件权限测试。
- PostgreSQL 17 集成测试、Ruff、严格 MyPy、前端类型检查与构建均通过。
- Docker 镜像构建和 Production Compose 解析通过。
- Worker 默认数据库池已统一为 `2 + 1`；4 Web 进程和 4 Worker 的最坏应用连接预算为 60。

该基线不是自动门禁；任务 01 完成后才会对每次变更强制执行。

## 总目标

在不改变 PostgreSQL 队列事实来源和单机首发拓扑的前提下，使系统满足公网、小流量、可收费生产发布要求，并具备可重复构建、可观测、可恢复和可回滚能力。

## 阶段与退出标准

### 阶段一：发布可信

- 01 自动化质量与发布门禁
- 02 可重复构建与供应链安全

退出标准：任何测试、类型、迁移、构建或高危漏洞失败都会阻止镜像发布；发布物可以追溯到源码、锁文件、SBOM 和镜像摘要。

### 阶段二：公网安全

- 03 认证防滥用与登录风控
- 04 HTTP 安全边界与画布 XSS 加固

退出标准：注册、登录和邮件接口具备跨进程限流；Host、代理、TLS 与安全头边界明确；恶意画布/工作流输入不能执行脚本或窃取会话。

### 阶段三：云端落地

- 05 单机云基础设施与 HTTPS 入口
- 06 云密钥与媒体存储策略

退出标准：基础设施由代码或受控配置复现；数据库、磁盘、网络、证书、Secret 与对象存储边界均有明确所有者和最小权限。

### 阶段四：可运维

- 07 自动备份与恢复演练
- 08 可观测性与告警

退出标准：数据库、媒体和密钥可以按同一恢复点恢复；关键失败能在用户报告前触发告警，并可通过请求、任务和上游标识定位。

### 阶段五：收费发布

- 09 支付与账户运营阻塞项
- 10 预发布端到端验收
- 11 容量复验、灰度发布与回滚

退出标准：真实 SMTP、Provider 和支付闭环验收通过；运营异常有处理路径；容量达到目标；可以灰度、观察并在规定时间内回滚。

## 统一执行方式

每个任务严格按以下顺序完成：

1. **分析问题**：复现现状、记录证据、确认威胁或故障模式，不先写补丁。
2. **设计方案**：明确边界、数据模型、失败语义、回滚方式和 ADR 冲突；评审通过后实施。
3. **修改代码**：代码、配置、迁移、脚本、文档和测试同一任务交付。
4. **质量检测**：运行定向测试与完整门禁，在预发布环境验证真实依赖。
5. **完成任务**：把结果、命令、指标、镜像摘要和回滚点追加到任务的 `## Comments`。

## 全局质量命令

```powershell
cd backend
& .venv/Scripts/python.exe -m ruff check app tests scripts
& .venv/Scripts/python.exe -m mypy app
& .venv/Scripts/python.exe -m pytest

cd ../frontend/admin
npm ci
npm run check
npm run build

cd ../..
docker compose --env-file deploy/.env -f deploy/compose.production.yml config --quiet
docker build -t creative-studio:<candidate> .
```

完整 CI 还必须提供 `POSTGRES_TEST_DATABASE_URL`，使 PostgreSQL 专属测试不被跳过。

## 非目标

- 首发阶段不改为 Kubernetes 或多主机部署。
- 不用 Redis/RabbitMQ 替换 PostgreSQL 队列。
- 不在未选定云厂商和区域前创建真实云资源。
- 不把单次 `/readyz` 压测结果当作 Provider 生图吞吐结论。
