# CI 触发去重

## 背景

功能分支推送并创建 Pull Request 后，`quality-gate` 与 `supply-chain` 会分别以 `push` 和 `pull_request` 事件执行两次。两类事件使用不同 `github.ref`，现有并发取消无法消除重复运行。

## 目标

每个 PR 提交只运行一套 PR 门禁，同时保留合并到 `main` 后的验证、手工执行和 `v*` 标签签名发布路径。

## 阶段与退出标准

1. **分析问题**：用真实 Actions 运行确认同 SHA 的重复事件与成本。
2. **设计方案**：定义 PR、默认分支、标签和手工触发矩阵。
3. **修改代码**：收紧 workflow 触发条件，增加合同测试并更新运维文档。
4. **质量检测**：本地测试后创建 PR，确认功能分支不再产生 `push` 工作流且必需检查全部通过。
