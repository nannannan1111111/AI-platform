# V33 工作台渐进加载

## 基线

- 基于已部署 V32 分支 `codex/v32-canvas-result-recovery-admin-prompt-redaction`、本地 HEAD `2c7ecd6`。
- V32 生产镜像摘要为 `sha256:a0be4436d537ae85678bc931faecd288b5330d382711b4e662175abf18dcc9d0`。
- 不修改任务创建、Worker 提交、扣费、退款或额度流水规则。

## 实施结果

- 画布列表先展示缓存或服务端元数据，再以 4 路受控并发回填单张缩略图；生成中画布每 15 秒只查询仍在生成的画布。
- 编辑器先返回保存的节点、连线和视口；任务恢复、媒体可用性和缩略图在后台完成，结果通过 `saas-canvas-hydrated` 合并。
- 会话快照只保存稳定画布 JSON，不保存 Blob URL；重进先使用快照，再后台向服务端校验。
- 图片页先展示任务摘要，历史结果以 3 路任务/媒体受控并发恢复；活动任务继续沿用 SSE 和受控轮询。
- 未改变任务创建、扣费、退款、额度流水、媒体清理、原图按需读取和 Worker 并发策略。

## 目标

1. 无限画布列表先显示画布元数据，再以受控并发加载缩略图。
2. 生成中画布只刷新对应预览，不再周期性重载整个列表。
3. 智能画布先渲染保存的节点、连线和视口，再后台恢复任务与媒体缩略图。
4. 历史成功任务不因已过媒体重复执行长时间入库等待；刚完成任务继续保留 V32 有界恢复。
5. 图片生成页先恢复任务摘要，再增量加载结果缩略图。

## 数据安全

- 只读取既有任务、画布和媒体，不重提上游任务。
- 不删除或改写用户画布、媒体、生成记录和额度流水。
- 缩略图继续优先，原图仅在放大、编辑或下载时读取。

- 运行 Web UI、画布恢复、SSE/轮询和媒体定向测试，前端构建、JS/Python 语法及 `git diff --check`。
- 生成 V33 候选镜像，保留 V32 回滚标签；Web 与 10 个 Worker 必须使用同一摘要。
